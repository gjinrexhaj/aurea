Why --ui-on-accent exists

The accent inverts luminance between themes: #017dd3 (dark) in light mode, #63b3ff (light) in dark mode. Any element that fills with the accent must therefore flip its ink too. Toggle the theme to see the active tool button and preset chip above flip from white to near-black ink.

Theme Fill Ink Ratio WCAG AA
Light #017dd3 #ffffff 4.30:1 ⚠ marginal (needs 4.5:1)
Dark #63b3ff #ffffff 2.23:1 ❌ fails
Dark #63b3ff #11141a (--ui-on-accent) 9.2:1 ✅ passes

The light-mode 4.30:1 is a known, documented deviation: the accent is a saturated brand hue used for 12px uppercase labels, and darkening it would break the palette.

Layout Pitfalls

100vw is banned

It includes the classic scrollbar width and produces a horizontal overflow of exactly that many pixels. Use 100%.

Flex children need min-* : 0

A child with height: 100% inside a flex column that also renders a sibling overflows its parent. Use flex: 1; min-height: 0.

overflow: hidden clips overhang

The floating window's four resize handles sit at -7px on each edge; the shell must not clip them.

Dark Mode Implementation Principles

1. Avoid Pure Black Canvas

Sunken canvas viewport uses #11141a, while raised surfaces use #1d222b to establish true depth and elevation.

2. Measured Contrast Ratios

Against #15181e: ink 15.9:1, ink-dim 11.0:1, ink-faint 7.98:1, accent 7.98:1. Ink-faint against #1d222b is 6.11:1 — still AA.

3. Tinted Alpha Borders

Use rgba(208, 216, 233, 0.22) rather than opaque grays, allowing background luminance to naturally soften edges.

4. Interactive Accents

Active selection and hover fills scale up alpha (from 3–4% to 12–16%) to preserve visibility against dark backdrops.

5. Set color-scheme

So native checkboxes, <select> popups, number-input spinners and default scrollbars follow the theme. Without it, dark mode renders light native controls on a dark surface.

6. Flip --ui-on-accent

Never hard-code white text on an accent fill. See Shared Tokens.

⚠ CSS Pitfalls & Guardrails

The checklist to run before merging any CSS change. Each item below is a defect that actually existed in this codebase and has been fixed.

1. Never @import a webfont

@import is fetched after the importing stylesheet parses, serialising a second request that blocks first paint. Aurea had the identical Google Fonts URL in four files. Fonts now load once from index.html via <link> + preconnect.

2. Never hard-code theme colours

~40 literal rgba(1,125,211,…) / rgba(99,179,255,…) values each paired with an .app.app-dark twin. An .app.app-dark colour override is now a code smell — it means the value should have been a token.

3. Never put #ffffff on an accent fill

2.23:1 in dark mode. Use var(--ui-on-accent). See Shared Tokens.

4. Never use the pure status hue for body text

#b7791f amber on #fff3cd = 3.3:1; on white = 3.6:1. Info text on --accent-soft = 3.4:1. All fail AA. Alert text must use --ui-*-text.

5. Never remove a focus indicator

.snap-radius-number { outline: none } left only a background tint, which vanished on the sunken input fill (WCAG 2.4.7). Use :focus-visible; never :focus, which also fires on mouse press.

6. Never transition: all

It animates layout-affecting properties you never intended to touch. .snap-preset-btn thrashed layout on hover. Enumerate the properties instead.

7. Never request weight 700 from a Plex family

IBM Plex Sans/Mono are only loaded at 400/500/600. font-weight: bold makes the browser synthetically faux-bold the 600 face. Use 600.

8. Never use 100vw for layout

It includes the classic scrollbar width and produces a horizontal overflow of exactly that many pixels. Use 100%.

9. Watch overflow: hidden + overhanging children

.window-shell { overflow: hidden } clipped all four resize handles positioned at -7px, silently disabling window resizing. The shell now lets its children overhang.

10. Never height: 100% on a flex child with siblings

.console-content at height: 100% inside a flex column that also renders .console-controls pushed the controls out of the panel. Use flex: 1; min-height: 0.

11. Never declare generic tokens on :root

ManualPage.css wrote --bg, --ink, --accent, --border, --radius-s on :root while only .manual-container consumed them — a namespace collision waiting to happen. Page tokens belong on the page container.

12. Never duplicate shared chrome

The confirm / colour / file dialogs were three verbatim copies of the same ~90 lines. They now share src/ui/Dialog.css. Before adding a fourth variant, extend the shared file.

13. Never re-declare global scrollbars

They were duplicated in global.css, ConsolePanel.css and ManualPage.css — and the manual copy omitted the Firefox scrollbar-color fallback, so Firefox rendered a light scrollbar on the dark manual page.

14. Never assert scoping you have not verified

LandingPage.css opened with “All rules are scoped under .landing-page-landing” while ~60 selectors were top-level. Every rule is now genuinely nested, and the file declares a scope contract: it is self-contained and must not consume --editor-* / --ui-*.

15. Never invent off-scale values

Font sizes 0.64 / 0.65 / 0.68 / 0.78 / 0.8 / 0.82rem and 10px; spacing 11 / 52 / 76 / 80 / 100px. All normalized to the scales in Spacing & Radii.

16. Never word-break: break-all on data text

It chops identifiers, ids and coordinates mid-token. Use overflow-wrap: anywhere.

17. Never ship an unreachable dark-mode rule

ManualPage.css carried a full dark palette behind body.app-dark .manual-container, .manual-container.app-dark — but the manual page has no theme switch, so neither selector ever matched. The palette was dead code.

Outstanding: manual page dark-mode wiring

The manual page's dark palette is now correct, but still has nothing to switch it on. To activate it, add a control that runs 

document.body.classList.toggle('app-dark');

or render .manual-container with an app-dark class. Until then the manual page is light-only by construction, not by accident.
